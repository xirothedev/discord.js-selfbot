## Repository layout

```text
apps/
├── docs/                 # this Fumadocs site
├── examples-js/          # runnable JavaScript examples
└── examples-ts/          # runnable TypeScript examples
packages/
├── discord-ts-selfbot/   # the published library
└── test-harness/         # fake Discord HTTP + WebSocket server
tools/
└── parity/               # differential harness against discord.js v14
docs/
├── adr/                  # architecture decisions
└── agents/               # issue tracker and triage conventions
```

## Commands

Run from the repository root:

```sh
bun install
bun run check
bun run lint
bun run fmt:check
bun run test
bun run build
bun run docs
bun run lint:boundaries
```

The docs app has extra commands:

```sh
bun run --cwd apps/docs dev
bun run --cwd apps/docs api
bun run --cwd apps/docs api:check
```

## Test seams

The test suite is organized around the boundaries where behavior is observable:

- **S1** — REST and gateway payloads, through `packages/test-harness`.
- **S2** — structures and builders.
- **S4** — managers.
- **S5** — selfbot-only behavior.
- **S6** — the public package surface.

Use the fake server instead of a real token. See `packages/test-harness/src/index.ts` for `apiResponses`, `responses`, `routes`, `respond`, and gateway dispatch helpers.

## Source

Every module under `src/` is TypeScript. Bun runs the `.ts` source directly. There is no JavaScript mirror to keep in sync.

The API prose store lives at `apps/docs/scripts/agent/api.json`. It was extracted once from the old source JSDoc. The source JSDoc is gone; update the store when a public description changes.

## Issues and pull requests

- Issues live in GitHub Issues. Use the `gh` CLI.
- Triage labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.
- Keep pull requests scoped to one slice.
- Add or update tests for behavior changes.
- Update the docs when a public API changes.

## Docs changes

The docs site is a static Next.js app. Content lives in `apps/docs/content/docs`.

- Manual pages are MDX.
- API pages are generated by `apps/docs/scripts/generate-api.ts`. Do not edit them by hand; edit `apps/docs/scripts/agent/api.json` or `typings/index.d.ts`.
- Run `bun run --cwd apps/docs api` after changing a public API.
- Run `bun run docs:agent` after changing a guide, example, or public description.
- Run `bun run docs` before you open a pull request that changes content.

## Decisions

- Architecture decisions live in `docs/adr/`.
- The domain glossary lives in `GLOSSARY.md`.
- The design contract lives in `DESIGN.md`.
